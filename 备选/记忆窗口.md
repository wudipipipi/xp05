# 记忆窗口

## 题目描述

某个系统会把最近处理过的消息保存在一个“记忆窗口”中。每条消息有三个属性：

- 编号 $id$；
- 当前 token 数 $t$；
- 重要性等级 $r$。

系统还有一个 token 上限 $W$。设当前仍在窗口中的所有消息 token 总和为 $S$。

系统需要依次处理 $q$ 个操作。每当加入一条新消息后，如果 $S>W$，系统会立刻进行维护。

维护过程如下：

1. 如果当前窗口中存在尚未被压缩过的消息，则选择一条消息压缩。
2. 被选择的消息满足：重要性等级 $r$ 最小；若 $r$ 相同，则编号 $id$ 最小。
3. 若这条消息当前 token 数为 $x$，压缩后变为

   $$
   \left\lceil\frac{x}{2}\right\rceil.
   $$

4. 每条消息最多只能被压缩一次。
5. 重复以上压缩过程，直到 $S\le W$，或者当前窗口中的消息都已经被压缩过。
6. 如果所有当前消息都已经被压缩过，但仍有 $S>W$，则不断删除最早进入窗口的消息，直到 $S\le W$。

你需要模拟这个系统，并回答查询。

## 输入格式

第一行包含两个整数 $q,W$，分别表示操作数和 token 上限。

接下来 $q$ 行，每行表示一个操作，格式为以下三种之一：

- `ADD id t r`：向窗口末尾加入一条消息，编号为 $id$，token 数为 $t$，重要性等级为 $r$；
- `ASK id`：查询编号为 $id$ 的消息是否仍在窗口中；
- `STAT`：查询当前窗口状态。

保证所有 `ADD` 操作中出现的 $id$ 两两不同。

## 输出格式

对于每个 `ASK` 和 `STAT` 操作输出一行。

对于 `ASK id`：

- 若编号为 $id$ 的消息仍在窗口中，输出它当前的 token 数；
- 否则输出 $-1$。

对于 `STAT`，输出两个整数 $cnt,S$，其中 $cnt$ 表示当前窗口中的消息数量，$S$ 表示当前窗口中的 token 总和。

## 样例

### 样例输入

```text
13 10
ADD 1 6 5
ADD 2 7 1
ASK 2
STAT
ADD 10 5 3
ASK 1
ADD 11 4 5
STAT
ADD 12 8 5
STAT
ASK 2
ADD 3 9 1
STAT
```

### 样例输出

```text
4
2 10
3
3 9
3 9
-1
2 9
```

### 样例解释

加入消息 $1$ 后，$S=6\le10$。

加入消息 $2$ 后，$S=13$，需要压缩。当前未压缩消息中，消息 $2$ 的重要性等级最小，因此将它从 $7$ 压缩为 $4$，此时 $S=10$。所以 `ASK 2` 输出 $4$，随后 `STAT` 输出 `2 10`。

加入消息 $10$ 后，先压缩消息 $10$：$5\to3$，再压缩消息 $1$：$6\to3$，所以 `ASK 1` 输出 $3$。

加入消息 $11$ 后，压缩 $11$：$4\to2$，仍然超限，于是删除最早的消息 $1$，窗口中剩下消息 $2,10,11$，总和为 $9$。

加入消息 $12$ 后，压缩 $12$：$8\to4$，再删除最早仍在窗口中的消息 $2$，因此之后 `ASK 2` 输出 $-1$。

最后加入消息 $3$，压缩 $3$：$9\to5$，再依次删除消息 $10,11$，剩下消息 $12,3$，总和为 $9$。

## 数据范围与约定

对于所有测试数据，保证：

- $1\le q\le 2\times 10^5$；
- $1\le W\le 2\times 10^{14}$；
- $1\le id,t,r\le 10^9$；
- 所有 `ADD` 操作中的 $id$ 两两不同。

本题采用测试点捆绑计分，同一子任务内的所有测试点均通过才能获得该子任务分数。

| 子任务 | 测试点编号 | 分值 | $q$ | 特殊性质 |
| :--: | :--: | :--: | :--: | :--: |
| $1$ | $1 \sim 2$ | $8$ | $\le 200$ | 无 |
| $2$ | $3 \sim 4$ | $8$ | $\le 2\times 10^5$ | A |
| $3$ | $5 \sim 8$ | $14$ | $\le 2\times 10^5$ | B |
| $4$ | $9 \sim 12$ | $14$ | $\le 2\times 10^5$ | C |
| $5$ | $13 \sim 20$ | $24$ | $\le 2\times 10^5$ | D |
| $6$ | $21 \sim 30$ | $32$ | $\le 2\times 10^5$ | 无 |

特殊性质 A：任意时刻加入新消息后都有 $S\le W$，因此不会触发维护。

特殊性质 B：所有消息的重要性等级 $r$ 相同，且 `ADD` 操作中的 $id$ 按加入顺序严格递增。

特殊性质 C：保证维护过程中不会发生删除消息的操作。

特殊性质 D：所有消息的重要性等级满足 $1\le r\le 30$。
